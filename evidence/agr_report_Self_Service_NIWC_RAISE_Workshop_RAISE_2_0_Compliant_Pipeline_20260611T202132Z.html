EXECUTION ANALYSIS
Current Execution (Run #15) — Stage-Only Run, Partial Data
Run #15 is a single-stage execution of RAISE_Gate_5_DAST_Scans only (still running at assessment time). The CI build/scan stage and approval stage were not executed in this run. No STO findings were returned by the API for this execution — either the ZAP DAST scan had not yet completed or returned zero findings. Framework: NIST RA-5, CA-7 — residual risk assessment against this execution is incomplete. Full-pipeline residual data drawn from last completed full-pipeline runs below.
STO Scanner Advisory Mode — Findings Do Not Block Pipeline
All STO scanners (Gitleaks, Semgrep, OWASP, OSV, AquaTrivy, ZAP) are configured with failureStrategies: type: Ignore on most steps or have no fail_on_severity threshold. This means the pipeline will complete successfully regardless of critical vulnerability findings. Prior runs show status IgnoreFailed — confirming scanners produced findings but did not block execution. Risk: Vulnerable artifacts can be signed, attested, and pushed to the registry without any blocking gate. Framework mapping: SOC2 CC7.2 | NIST RA-5, SI-2 | cATO 3.2 | PCI 6.3.1
SBOM Generated But Never Policy-Enforced
The pipeline generates a Syft SBOM in spdx-json format and attests it with cosign keys. However, no SscaEnforcement step validates the SBOM against component allow/deny policies. An attested SBOM containing prohibited or vulnerable components will pass the pipeline without triggering any enforcement action. Risk: Supply chain component risk is documented but not mitigated at pipeline execution time. Framework mapping: SOC2 CC7.2 | NIST SR-3, SR-11 | SLSA L2 | cATO 3.1 | PCI 6.3.1
No OPA On-Run Policy — Save-Time Gate Bypassable
The RAISE_2_0_Pipeline_Governance policy set evaluates on onsave only. A pipeline that was previously saved and passed governance can be executed multiple times without any on-run policy re-evaluation. If pipeline YAML is modified via API (bypassing the UI save flow), the onsave gate may not trigger. Fix: Add a companion policy set with action=onrun and Error and Exit behavior. Framework mapping: SOC2 CC5.2 | NIST CA-7, CM-3 | cATO 3.2 | PCI 6.5
Build Tool Image Not Digest-Pinned (SLSA L3 Gap)
The Application_Build step uses node:20-alpine (floating tag) and the container build step relies on the Harness Cloud runner without an explicit image digest reference. For SLSA Level 3 provenance, every build tool that touches the codebase or produces an artifact must be immutably referenced. A substituted or compromised node image could inject malicious code that survives all downstream security scans. Framework mapping: SOC2 CC7.1 | NIST SA-12, SR-4, SI-7 | SLSA L3 | cATO 3.1 | PCI 6.2
Evidence Persistence Gap — Scanner Outputs Not Durably Stored
While the pipeline generates a signed SBOM attestation via cosign, individual STO scanner outputs (Semgrep SAST findings, Gitleaks secrets report, OWASP/OSV SCA results, AquaTrivy CVE report, ZAP DAST findings) are not explicitly exported to a durable artifact store. These findings exist in Harness STO dashboards during the execution window but may not satisfy long-term evidence retention requirements for cATO continuous ATO maintenance or PCI DSS audit artifact requirements. Framework mapping: SOC2 CC4.1 | NIST CA-2, CA-7(1) | SLSA L2 | cATO 1.0 | PCI 12.4
